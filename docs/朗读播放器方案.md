# 朗读播放器方案（texte.html）

> 目标：①「朗读全段」与「全文 MP3」两个入口都具备 **暂停 / 继续 / 停止**，暂停后从中断处继续；② 朗读中**实时高亮当前句**并**自动滚动到可见区域**。
> 状态：**P0 已实施（2026-10-29）**，Jian 拍板：句级重读、不做字幕、隐藏页面时 TTS 暂停 + MP3 继续。
> 落地：`assets/js/player.js`（DhPlayer）、`deutsch.js` 的 `renderTexts`、`annotate.js` 的 Esc 与语速联动、`deutsch.css` 高亮与播放器条样式；回归脚本 `scripts/_test_player.py`（34 断言）。
> P1/P2（字幕驱动词级高亮与 seek、Media Session、跨会话断点续听）暂未做，保留下方取舍表备查。

## 一、现状与硬约束（已核实）

| 事实 | 位置 | 影响 |
|---|---|---|
| 「朗读全段」= `window.__dhSpeak(全文)`，一次性 speak 约 1549 字符 | `deutsch.js:901` / `annotate.js:120` | 无暂停/继续、无高亮、无法定位到句 |
| 「全文 MP3」/ 段落 🎧 = 单例 `Audio()`，`src=` 后 `play()` | `deutsch.js:835-842`、`903`、`915` | 每次从头开始，无进度、无停止；`onerror` 回退在线 TTS 会丢失进度 |
| 句级 🔊 = `__dhSpeak(单句)` | `deutsch.js:516` | 只能单句，不能连读 |
| 语速三档已存在（慢 0.66 / 正常 0.88 / 快 1.10，localStorage `deutschheft_srate`） | `annotate.js:109-131`、`305-319` | **只作用于 TTS**；MP3 需另接 `audio.playbackRate` |
| Esc 停止已实现（仅 speechSynthesis） | `annotate.js:140` | 停止不了 MP3 |
| DOM 里每句已是独立节点 `.s-line`（内含 `.s-text`） | `deutsch.js:882-890` | 句级高亮零数据改造，只需加 class |
| 数据层 `ips` / `zhs` 与句子一一对齐（t3 = 29 句） | 已校验 | 可用「段-句」坐标寻址，无需 DOM 引用 |
| `renderTexts` 每次切页签/隐藏中文都 `innerHTML` 重写 | `deutsch.js:859` | 播放器**不能持有 DOM 引用**，必须按坐标重定位 |
| `annotate.js` 有 MutationObserver 监听 `#app` childList | `annotate.js:330` | class 变更不触发（仅子节点增删），但重建 DOM 会丢高亮 → 需重放 |

**浏览器能力边界（决定实现取舍）**
- `speechSynthesis.pause()/resume()`：Chrome 桌面长期存在 bug（resume 失效或 pause 立即 end），iOS Safari 不可靠 → **不作为断点续听的主机制**。
- `utterance.onboundary` 提供 `charIndex`：Chromium 系可用；Safari 有事件但 charIndex 常为 0；Firefox 不支持 → **词级高亮必须能降级**。
- iOS Safari 单条 utterance 有长度上限（约 200–300 字符会静默截断）→ **分句朗读顺带解决长文本截断**。
- `<audio>` 在 iOS 切后台会被挂起、并受静音拨杆影响；Web Speech 同样受限 → 真正的后台连续播放不可承诺。

## 二、P0 设计（本次实施）

### 1. 新增 `assets/js/player.js`（约 180 行，单一职责）
`DhPlayer` = 源无关的状态机 + 队列 + 高亮调度：

```
状态：idle → playing → paused → ended → idle
API：playTTS(items) / playMp3(src, opts) / pause() / resume() / stop() / seekSentence(i)
事件：onState、onSentence(i)、onProgress(pct)
```

### 2. 断点续听（关键取舍）
- **不依赖 `speechSynthesis.pause()`**。改为**句级队列**：句子数组逐句 `speak()`，维护 `i`；
  - 暂停 = `cancel()` 当前句并保留 `i`；
  - 继续 = 从 `i` 这一句重新朗读（最多回退一句，约 2–4 秒）；
  - 停止 = `cancel()` + `i=0` + 清除高亮。
- MP3 源：`pause()` / `play()` 原生支持，天然从中断处继续（无需额外逻辑）。
- 取舍：句级回退 vs 无回退但不稳的原生 pause —— **推荐句级**（跨平台一致、代价可接受），且顺带解决 iOS 长文本截断。

### 3. UI：课文页按钮区改为播放器条
`▶ 播放/⏸ 暂停` + `⏹ 停止` + 状态文字（第 N 段 · 第 i/29 句）+ 进度条；
同一条 UI 服务两个入口：点「朗读全段」= TTS 源，点「全文 MP3」= 音频源。
句级 🔊 建议升级为「**从该句开始连读到段尾**」（成本低，学习体验明显更好）。

### 4. 高亮与自动滚动
- 当前句 `.s-line` 加 `.s-reading`（CSS：左侧色条 + 底色，浅/深双主题）；同时移除上一句。
- 滚动：仅当目标不在视口内才 `scrollIntoView({ block: "center" })`；`prefers-reduced-motion` 时用 `auto`。
- 只切 class，不重建 DOM；重渲染后按「段-句」坐标重放高亮。

### 5. 生命周期
切换课文页签 / 切换隐藏中文 → `stop()`；`pagehide` / `beforeunload` → `stop()`；`annotate.js` 的 Esc 改为 `DhPlayer.stop()`（同时停 TTS 与 MP3）。

## 三、建议项：场景与取舍

| 项目 | 建议 | 适用场景 | 代价 / 取舍 |
|---|---|---|---|
| **高亮粒度：句级** | P0 默认 | 全部平台、长篇跟读 | 精度 = 一句（2–4 秒），但零数据改造、行为一致 |
| **高亮粒度：词级** | P1，用 `onboundary.charIndex` | 精读、逐词跟读训练 | 仅 Chromium 可靠；Safari/Firefox 自动降级到句级；需维护字符偏移映射 |
| **MP3 句级同步** | P1，用 `edge-tts --write-subtitles`（已验证支持）生成 SRT，前端按 `currentTime` 匹配 | 想让 MP3 也有高亮与「跳到某句」 | 构建产物 +N 个字幕文件 + 解析代码；MP3 时长与句子映射需回归测试 |
| **MP3 进度条 + 拖拽 seek** | P0 可做 | 长音频定位 | 仅 MP3 精确；TTS 只有句进度（离散），不要伪装成连续进度条 |
| **系统级后台控制** | P1，Media Session API（标题 + play/pause 处理） | Android / 桌面 Chrome 锁屏控制 | iOS Safari 支持有限且切后台会挂起音频；只能承诺「元信息与控制」，不能承诺连续后台播放 |
| **语速** | 复用现有三档，同时映射到 MP3 的 `playbackRate`（`preservesPitch` 默认 true，不失真） | 慢速精听 / 快速复习 | 两个源基准不同（MP3 预生成已 -5%），叠加后体感略有差异；保留三档（与既有习惯一致）胜过加滑杆 |
| **断点续听（跨会话）** | P1，localStorage 存 `{textId, source, paraIdx, sentIdx, time, hash}`；进入页面提示「上次听到第 2 段第 3 句 · 继续 / 清除」 | 长篇课文分次听完 | 数据编辑会让索引漂移 → 存句子前 20 字哈希校验，不匹配即丢弃；存储 <1KB |
| **性能与内存** | 队列同时只存在 1 个 utterance；高亮只切 class；MP3 用 `timeupdate`（约 4Hz）而非 rAF 常驻轮询 | 低端设备 / 移动端 | 词级高亮会提高到 10Hz 级事件，需节流 |
| **长文本** | 分句 + 句间 150–250ms 自然停顿；超长句（>200 字符）按逗号二次切分 | t3 全文 1549 字符、未来更长课文 | 停顿过长显得断续，过短则句间粘连，需实测调参 |
| **切换段落 / 课文** | 播放器持「段-句」坐标而非 DOM 引用；切换即 `stop()` 并清高亮 | 切页签、隐藏中文重渲染 | 「切换即停」简单可预期；若想要「跨段落连读」需队列拼接（复杂度上升，不建议 P0） |
| **页面跳转** | 多页站点跳转即卸载：`pagehide` 停 + 存进度 | 从课文页跳去生词表 | 无法跨页续播（除非改成 SPA 或音频页），保持简单 |
| **移动端** | 首次播放必须在用户手势内（按钮点击天然满足）；句 🔊 改连读；`visibilitychange` 时 **TTS 暂停、MP3 保持** | 手机锁屏听 MP3 | iOS 静音拨杆会静音 `<audio>`（改 WebAudio 成本高，不建议）；Android 表现好于 iOS |
| **无障碍 / 键盘** | Esc 停止（已有）、按钮支持 Space/Enter、`aria-live` 播报播放状态 | 键盘用户、读屏 | 全局 Space 会与页面滚动冲突 → 只在播放器按钮聚焦时绑定 |

## 五、验证计划（Playwright，约 12 条断言）

1. 点「朗读全段」→ 出现暂停/停止按钮，第 1 句带 `.s-reading`
2. 暂停 → 高亮句保持、状态为 paused；继续 → **不是从第 1 句开始**
3. 停止 → 高亮清除、按钮回到播放态
4. 全文 MP3 → 进度条随时间推进；暂停/继续后 `currentTime` 连续
5. 高亮唯一性：任意时刻 `.s-reading` 数量 = 1
6. 自动滚动：目标句进入视口（`boundingBox` 在视口内）
7. 切换课文页签 → 播放停止、无残留高亮
8. 隐藏中文切换 → 播放停止、重渲染后无报错
9. 段落 🎧 与句 🔊 均走同一播放器，互斥（不会两路同时出声）
10. Esc 同时停止 TTS 与 MP3
11. 移动端视口（390×844）控件不溢出、可点
12. 无 JS 报错
